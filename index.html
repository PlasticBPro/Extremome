Extremome · Public Project Overview

Extreme-environment metagenomics, organized as one reproducible research system.

Extremome is building a shared path from public extreme-environment sequencing records to comparable metagenomic outputs, downstream functional analysis, and eventually paper-facing evidence. This page is the public reading layer: it explains the project structure and current work without exposing private operational infrastructure or unpublished scientific detail.

What the project is trying to make possible

Our immediate goal is to make extreme-environment metagenomic datasets genuinely comparable before drawing biological conclusions from them. That means preserving sample and Run identity, processing datasets through a consistent upstream workflow, keeping both molecular sequence information and microbial carrier information, and fixing the exact versions used by downstream analysis.

SOURCE

Start from qualified public records

Papers, archive accessions, Run-level metadata and source context are collected into a shared baseline rather than separate personal lists.

UPSTREAM

Process data reproducibly

QC, assembly, mapping, gene calling and carrier recovery are executed through a versioned workflow with recoverable provenance.

ANALYSIS

Compare fixed outputs

Downstream analyses consume explicit upstream versions instead of an unspecified “latest” dataset or method state.

PAPER

Connect claims back to evidence

Figures, source data, analysis code and exact dependencies are kept linked as the manuscript becomes evidence-bearing.

The research pipeline at a glance

This is the public scientific and engineering spine. Detailed internal qualification layers, cluster operations and unpublished analysis logic are intentionally not reproduced here.

01 · SOURCE BASELINE

Papers + public sequencing records

Resolve source context, accessions and Run-level metadata; keep uncertainty rather than forcing missing values.

02 · INPUT + QC

Verified sequencing inputs

Confirm identities and paired reads, then apply a consistent read-quality workflow.

03 · RECONSTRUCTION

Assembly + molecular space

Assemble each scientific observation and retain protein and gene occurrences across eligible contigs.

04 · CARRIER RECOVERY

Microbial context

Recover genome-level carrier information where supported while keeping unresolved links explicit.

05 · ANALYSIS

Versioned comparison + paper evidence

Use fixed upstream outputs for functional and ecological comparisons, then connect stable results to figures and manuscript claims.

Engineering completion is not a biological conclusion.

A successful workflow run does not by itself prove enzyme function, biological absence, sample independence or paper readiness. Those questions are evaluated separately downstream.

How the GitHub work is divided

Extremome uses separate repositories because source curation, upstream processing, downstream analysis and manuscript composition change at different rates and have different review needs. Four repositories form the core research chain; a separate web repository supports result access and visualization. At this snapshot the working repositories are private team repositories; this page is the public project entrance.

How a change moves through the team

We use GitHub as a review surface, not as a replacement for scientific judgment. Small fixes can be proposed directly; larger changes normally start from an Issue so the scope and evidence are visible before the shared branch changes.

1. IssueDescribe the problem, source, method or change.
2. BranchWork from the current shared base.
3. ChangeImplement, curate or analyze the scoped object.
4. CheckRun the relevant tests or integrity checks.
5. Pull RequestExplain what changed, why and how it was checked.
6. Human reviewShared changes are reviewed by Bohui (@bibobrain).
7. Merge + pinDownstream work records the exact version it uses.
Do not build paper-facing work from an unspecified “latest” revision.

Once a dataset, workflow or analysis becomes an input to another part of the project, the consumer should record the exact commit, batch or snapshot it used.
