Public overview v0.2.0 · 26 October 2026

From extreme-environment data to evidence-led research.

Extremome studies microbial communities and candidate enzymes associated with plastic-related transformation in extreme environments. The project combines curated public sequencing records, reproducible metagenomic processing, downstream analysis, and evidence-linked manuscript work.

Explore the workflow ↓Open the public site ↗
Scientific boundary: computational evidence can prioritize candidates, but it does not by itself establish measured enzyme activity or prove that a sample degrades plastic.

Research workflow

One connected process, with evidence retained at each step

The pipeline is being built around the available data, current computing resources, and the need to make outputs comparable and reproducible. The page shows the research-facing overview, not internal implementation or qualification layers.

01

Curate source records

Connect papers, archive accessions, environmental context, and sample/Run metadata. Keep source uncertainty visible.

02

Qualify and process inputs

Check input identity and quality, then run a documented workflow with recoverable inputs and outputs.

03

Reconstruct genomic context

Assemble sequence data and recover genes, proteins, and microbial context where the evidence supports it.

04

Compare candidate evidence

Combine sequence, evolutionary, structural, genomic-context, and environmental evidence rather than relying on one score.

05

Build checkable results

Use fixed inputs and versions for downstream analysis, then connect figures and interpretations to their supporting evidence.

High-performance computing supports large jobs, but this page is not a live job monitor and does not publish cluster paths, resource settings, or job-level identifiers.

How the team works

Issues define the work; Pull Requests make changes reviewable

GitHub is the shared review surface. The exact workflow depends on whether the work belongs to a private research repository or this public overview.

  1. Open an Issue for a real question or bounded taskExplain what needs attention, why it matters, and the relevant paper, data, method, or code. Avoid mixing unrelated changes.
  2. Work on a branchStart from the current shared base and keep the change focused.
  3. Open a Pull RequestState what changed, why, how it was checked, and whether a shared result or interpretation could change.
  4. Run checks and request human reviewAutomation can catch technical problems; shared changes are reviewed by Bohui (@bibobrain) before they are merged.
  5. Merge, then pin the version used downstreamWhen another analysis depends on the change, record the exact commit or data snapshot rather than relying on a moving latest branch.

Where to raise a question

Issues are used inside the private research repositories to coordinate production, analysis, and manuscript work. Issues are currently disabled on this public overview repository, so public-facing corrections should be proposed as a Pull Request. See the contribution guide for the intended scope.

  • Do not post private issue numbers or comment excerpts here.
  • Do not upload credentials, private paths, restricted metadata, raw data, or unpublished candidate-level results.
  • A successful check or merge is not, by itself, a scientific conclusion.
